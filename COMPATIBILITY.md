# Совместимость Quard 1.1.0

Для экспериментального первого in-memory exact-pass (#114) зафиксированы
`quard-clones 0.1.0` и связанные Rust-крейты в `tools.json` и Cargo.lock.
`QUARD_CLONE_ENGINE=rust` требует wheel в окружении потребителя; несоответствие
версий либо исходных фрагментов даёт инфраструктурную ошибку (exit 2).
Три обычных CLI-прохода остаются доступны до проверки остальных проходов по
#112 и публикации и закрепления wheel для обычной установки в #125.
Контракт и компромисс описаны в [ADR 0005](docs/adr/0005-in-memory-native-clone-engine.md).

Историческое происхождение: установленный Python Quality 1.0.0 в tai.
Ниже сохранены обоснования исправлений; актуальные команды используют Quard.

Поставка установлена в tai 2026-09-21. Реальные smoke-тесты установщика прошли;
версии инструментов сохранены в `tools.json`. В полном прогоне на проекте выявлены
и исправлены две ошибки исполнения:

1. `check.py`: каталог `raw/` создаётся при подготовке задач, до старта анализаторов.
   Pylint открывает файл `--output` сразу; раньше создание каталога зависело от того,
   успел ли другой анализатор завершиться и сохранить stdout/stderr.
2. `_pylint_worker.py`: локальная совместимость с Pylint 4.0.8 для алиасов методов
   pathlib, например `write_text = Path.write_text; write_text(...)`. Нативный
   `_check_open_call` обращается к `attrname` у AST-узла `Name`, где этого поля нет.
   Обёртка временно предоставляет уже определённое имя функции и вызывает исходную
   проверку; после вызова AST восстанавливается. Правила `bad-open-mode` и
   `unspecified-encoding` продолжают выдавать диагностику.

Регрессии проверяются настоящим Pylint в изолированных временных проектах:

```bash
uv run --locked --group dev python -B -m unittest discover -s quard/tests
```

Тесты проверяют первый запуск с новым каталогом отчёта, сохранение native JSON,
диагностику неизвестного имени, неверного режима открытия и отсутствующей кодировки,
а также отсутствие ошибки на вызове с явно заданной кодировкой.

Для обычной установки клона используйте `uv sync --locked --group dev`. При обновлении
Quard исправления входят в версионируемый код инструмента. Установщик не изменяет
`quard/check.py` и `quard/_pylint_worker.py`. После обновления
Pylint пересмотрите необходимость обёртки и выполните регрессионные тесты и полный check.

Исторически после выделения контрактов, выполнения, I/O и сборки `tach.toml` tai
содержал 97 файловых границ. При выделении Quard принято уже 109 модулей; источник
истины — конфигурация потребителя, а не это историческое описание.
Зависимости сверены с импортами; интерфейсы пакетов соответствуют `__all__`,
листовые модули экспортируют публичные символы. Строгая матрица слоёв сохранена:
`cannot_depend_on` дополнительно запрещает Interface → Infrastructure и
Infrastructure → UseCase для всех соответствующих файлов. Чистые значения ALERT
и журнала отделены от файлового I/O; выполнение FITD/preflight/серии зависит от
контрактов, а сборка конкретных участников находится в Bootstrap. Конфигурация и
порты журнала (`journal_configuration`, `journal_ports`, `journal_support`) относятся
к Domain; изменяемый контекст захвата ошибок `app.failure_capture` — к UseCase.
Выделенный нативный адаптер `attacks.fitd.probe` остаётся в Infrastructure.
`init_architecture.py` сохраняет Bootstrap при передаче карты clean-architecture-
плагину: прежняя подмена на Interface теряла разрешённые связи сборки с адаптерами.
`tests/quard/clean_architecture_layers/test_configured_clean_architecture_layers.py` закрепляет сохранение всех пяти слоёв,
приоритет точных модулей и сохранение посторонних настроек/комментариев при повторной
генерации карты.
Назначение структуры описано в корневом `README.md`. `architecture.ready.json`
подтверждает принятие конфигурации, а не отсутствие нарушений в исходниках.

## Согласованная политика наследования garak

2026-09-22 пользователь принял текущую интеграцию: публичный `FITDProbe` реализует
`ProbeOperations`, внутренний `_NativeFITD` наследует закреплённый garak FITD.
В `ignored-parents` добавлен точный тип `garak.probes.base.Probe`. Pylint исключает
его и `Configurable` из подсчёта R0901; `FITD`, `IterativeProbe` и собственные
промежуточные классы учитываются. `max_parents = 3` сохранён. Это согласованная
политика внешнего каркаса, а не исправление ошибки Pylint. Она отражена в
`pyproject.toml` потребителя. В Quard garak отсутствует в общих defaults;
тестовый профиль синхронизируется через `quard/apply.py`, повторная установка
сохраняет native `ignored-parents` проекта.

W9201 продолжает проверять публичный фасад. Native checker уже пропускает
приватные helper-классы, поэтому `_NativeFITD` не требует Domain-контракта,
повторяющего служебный API garak.

## Совместимость с clean-architecture-linter-plugin 1.2.2

Эти исправления и карта `[tool.clean-arch]` применяются только к принятой
reviewed-конфигурации. Generated-проекты запускают обычный Pylint без плагина
в обоих профилях и без синхронизации карты слоёв. Исправления Pylint 4.0.8
для Protocol (R0903/E1111) продолжают работать в обоих режимах.

`architecture_compat_utils.py` исправляет воспроизводимые ошибки семантики закреплённой
версии; `_architecture_compat.py` сохраняет прежний путь импорта. Точка интеграции
в worker — вызов `install_architecture_compat()` **до**
`pylint.lint.Run(...)`, создающего и конфигурирующего checkers. Повторный вызов
безопасен; другая версия плагина требует пересмотра патча и вызывает ошибку.
Этот же installer вызывает `install_pylint_protocol_compat()` для описанного ниже
исправления Pylint 4.0.8; другая версия Pylint также требует явного пересмотра.
Изменения применяются в памяти процесса: файлы site-packages не редактируются,
сообщения не фильтруются, численные лимиты и native-конфигурации сохраняются.

Исследованы установленный код `clean_architecture_linter/{config.py,checks/*.py}`
версии 1.2.2 и [каталог правил upstream](https://github.com/noah-goodrich/pylint-clean-architecture/blob/main/RULES.md).
Исправления ограничены следующими доказанными расхождениями:

* **W9001 — разрешение импортов и текст сообщения.** Явное наиболее специфичное
  назначение слоя имеет приоритет над догадкой по имени каталога. Префикс модуля
  заканчивается на границе сегмента (`pkg.core` не совпадает с `pkg.core_io`).
  Относительные импорты и импортированные подмодули разрешаются через Astroid;
  реэкспорт символа проверяется по импортируемой публичной границе. Аргументы
  сообщения исправлены на «импортирующий слой → импортируемый слой»: upstream
  передавал их в обратном порядке. Для четырёх native-слоёв матрица сохранена,
  включая запрет Interface → Infrastructure. Явно настроенный **Bootstrap**
  поддерживается как composition root: может импортировать все слои, а другие
  слои не могут импортировать Bootstrap. Имя файла само по себе не даёт этот слой.
* **W9004 — внутренние импорты.** Настроенный Domain/UseCase распознаётся независимо
  от буквальных частей имени `domain/dto/use_cases/protocols/models`. Относительные
  импорты больше не проверяются как сторонние библиотеки. `__future__` разрешён
  как объявление возможностей компилятора, не операция I/O. Внешние `socket` и
  неклассифицированные библиотеки по-прежнему диагностируются; explicit outer-layer
  mapping не обходится присутствием слова `domain` в пути. Общего разрешения stdlib,
  внешнего I/O либо исключений по путям проекта нет.
  Дополнительно разрешены конкретные стандартные symbols, сами не выполняющие
  raw I/O: `types.TracebackType/MappingProxyType`, `threading.Event/Lock/RLock/Thread`,
  `urllib.parse.urlsplit/urlunsplit`, `shlex.quote`, `copy.deepcopy`. Thread/lock/event
  описывают локальную оркестрацию и синхронизацию выполнения, а не транспорт I/O.
  Для `from` каждый импортируемый symbol должен входить в этот перечень. Для
  `import module` проверяются все использования соответствующего binding: разрешены
  только обращения к этим symbols; передача модуля как значения или другой member
  сохраняет W9004. Проверяется происхождение из stdlib текущего интерпретатора,
  чтобы одноимённый проектный модуль не получил исключения. `socket`, `subprocess`,
  `urllib.request`, `concurrent.futures` и остальные члены модулей не освобождаются.
* **W9201 — настоящий Protocol в настроенном Domain.** Проверяется конфигурация
  слоя определения и выведенная база `typing.Protocol`/`typing_extensions.Protocol`,
  включая алиасы, квалифицированные и generic-базы. Одного суффикса `Protocol`
  недостаточно. Наследование через промежуточную реализацию поддерживается native
  обходом ancestors; дополнительные публичные методы вне контракта всё ещё дают
  W9201. Protocol в другом настроенном слое не становится Domain по написанию пути.
* **W9202 — объявления Protocol и overload.** Та же проверка выведенной базы позволяет
  отличать абстрактное объявление с алиасом/квалифицированной базой от concrete stub.
  Декораторы, достоверно выведенные как `typing.overload`/`typing_extensions.overload`,
  обозначают сигнатуры типов, а не concrete-реализации. Алиасы поддерживаются;
  пользовательский декоратор с именем `overload` не получает исключения.
  Тела concrete-методов из `pass`, `...` или `return None` по-прежнему диагностируются.
* **W9007/W9009 — происхождение типа.** Astroid возвращает литералы `None`, строки
  и контейнеры с lexical parent в исходном файле. Upstream ошибочно считал их
  инфраструктурными типами, если литерал записан в Infrastructure. Теперь для
  Instance проверяется определение его класса (`_proxied`), то есть `builtins`
  для литералов. В закреплённой версии Astroid узлы `Const`, `List`, `Dict`, `Tuple`
  и `Set` действительно являются Instance; реальные Pylint fixtures проверяют
  литеральные возвраты из инфраструктурного модуля, а не только обычные instances.
  Возврат/сохранение настоящего infrastructure object, а также
  исходные эвристики raw-types, продолжают диагностироваться.
  Явный наиболее специфичный слой определения имеет приоритет перед
  `infrastructure_modules`: Domain-класс в `pkg.records` не становится
  infrastructure object из-за инфраструктурного фасада `pkg`. Анализ raw-types и
  инфраструктурных предков сохраняется, включая внешние библиотеки.
  W9007 теперь сопоставляет имя и происхождение одного и того же inferred value:
  upstream мог найти raw object во второй ветви, но назвать `NoneType` из первой.
* **W9007 — composition wiring.** Фабрики в явно настроенном Bootstrap могут
  создавать и возвращать infrastructure object. Это не возврат raw data из
  Repository в Domain. Публичные методы классов `*Repository` и реализаций
  Domain Protocol продолжают проверяться даже при размещении в Bootstrap.
  Названия `bootstrap`/`composition` без явного назначения слоя не дают исключения.
* **W9007 — проверенные контракты возврата.** Infrastructure factory/helper может
  возвращать конкретную реализацию Domain Protocol, если точная return-аннотация
  и фактически выведенный класс согласованы. На публичной границе метода требуется
  аннотация самого Domain Protocol: concrete repository return type по-прежнему
  раскрывает реализацию и диагностируется. `object`, `Any`, отсутствие аннотации,
  подмена raw object аннотацией Protocol и наследование raw-type не дают исключения.
  Отдельно допускается `__enter__/__aenter__`, возвращающий доказанно тот же `self`
  с типом `Self`/собственного класса и парным exit-методом. Другой возвращаемый
  объект, переназначенный `self` и обычный метод с `return self` проверяются дальше.
* **W9003 — граница слоёв.** Upstream проверял всякий `_member`, кроме `self/cls`,
  хотя правило описывает доступ через границу слоёв. Достоверно выведенный владелец
  в том же модуле или том же настроенном слое не является пересечением границы.
  При неизвестном/неоднозначном владельце сохраняется native-проверка; доступ из
  другого слоя продолжает диагностироваться. Обычный Pylint `protected-access`
  остаётся независимой проверкой инкапсуляции.
  Отдельно распознаётся реальный builtin `super()`/`super(CurrentClass, self)`:
  освобождение возможно только для метода, найденного в MRO текущего экземпляра.
  Это поддерживает унаследованные hooks стороннего класса. Несуществующий hook,
  чужой private-объект и пользовательская функция с именем `super` не освобождаются.
* **W9006 — создание объектов и пространства имён.** Вызов выведенного конструктора
  создаёт локально принадлежащий объект, а не «чужой» результат метода. Выведенные
  модули/классы в квалифицированных вызовах не являются цепочкой объектов.
  `self.field.method()` upstream уже разрешает. Более глубокая объектная цепочка и
  вызов метода у результата чужого метода сохраняют native W9006.
  Для Domain-value exemption используется модуль определения типа, а не lexical
  parent значения. Если Astroid не выводит значение параметра или поля, учитывается
  достоверно разрешённая аннотация Domain-типа, включая injected bundles и первое
  собственное поле `self.dependencies`. Конкретный выведенный Infrastructure-тип
  и неоднозначный union с ним имеют приоритет: аннотация не скрывает такую цепочку.
  Это не разрешение произвольного поля чужого объекта или сторонних I/O типов.
  Если значение вызова неизвестно, аналогично используется точная return-аннотация
  выведенной функции либо метода аннотированной зависимости. Это покрывает
  `response = classify(...); response.to_string()` с Domain Message без подмены
  фактически выведенного инфраструктурного результата аннотацией.
  Доказанные builtin scalar values (`str`, `bytes`, `int`, `bool`, `float`, `complex`)
  также не являются графом чужих объектов: `raw.decode()` на bytes не получает
  W9006. Это точное сравнение типов; произвольный класс с методом `decode` и
  подклассы встроенных типов не получают такого исключения.
  Неаннотированный `pathlib.PurePath.with_name` (в Python 3.13 —
  `pathlib._abc.PurePathBase.with_name`) сохраняет тип получателя. Стандартные
  классы путей Python 3.13 определены в `pathlib._local`, вне native safe root
  `pathlib`; их происхождение проверяется по файлу stdlib. Переопределения и
  одноимённые методы других классов не получают исключения W9006.
* **Pylint R0903 — объявления Protocol как интерфейсы.** В `design_analysis.py`
  native-комментарий явно исключает interface classes, но Astroid классифицирует
  `typing.Protocol` как обычный class. Для этой проверки
  `install_pylint_protocol_compat()` расширяет только предикат
  `_is_exempt_from_public_methods` для настоящих Protocol declarations.
  Concrete subclasses Protocol и обычные классы с одним методом сохраняют R0903;
  R0901, R0904, max/min limits и список игнорируемых built-in ancestors не меняются.
* **Pylint E1111 — возвращаемое значение объявления Protocol.** Pylint 4.0.8
  рассматривает тело `...` у метода Protocol как concrete-функцию без `return`.
  Это воспроизведено для generic `Journal.call[T](...) -> T` через поле dataclass,
  а также для алиасов и квалифицированных/generic баз Protocol. В
  `TypeChecker._is_ignored_function` добавлено распознавание единственного `...`
  в теле метода настоящего объявления Protocol, аналогично native-обработке
  абстрактных методов. Методы с default-реализацией, concrete overrides и классы,
  только названные `*Protocol`, по-прежнему проверяются на E1111/E1128. Патч
  ограничен версией 4.0.8 и устанавливается тем же `install_pylint_protocol_compat()`.

`tests/quard/architecture_compatibility/test_pinned_architecture_compatibility.py` запускает настоящий Pylint в отдельных процессах
на временных пакетах: сравнивает проблемные примеры с непатченным плагином и
проверяет отрицательные случаи. Это изолирует singleton-конфигурацию плагина и
проверяет установку патча до загрузки plugins, включая повторный вызов installer.

```bash
uv run --locked --group dev python -B -m unittest discover -s tests/quard/architecture_compatibility -v
uv run --locked --group dev python -B -m unittest discover -s tests -v
```

### Диагностики, требующие ревью исходников

Патч не делает полный static check зелёным автоматически. В исходном отчёте были
реальные зависимости UseCase/Interface → Infrastructure, concrete chat/journal
classes без Domain Protocol, методы вне объявленного контракта, возвраты настоящих
инфраструктурных объектов и цепочки вроде `observation.journal.call(...)`.
Отдельные `return None` в `redirect_request` и `clear_history` могут быть намеренным
no-op по контракту сторонней библиотеки, но native W9202 явно включает такие тела:
это спор политики, а не доказанная ошибка распознавания, поэтому он сохранён.
W9007 в upstream применяется ко всем возвратам, несмотря на слово Repository
в сообщении; исключения ограничены описанными проверками wiring, контрактов и
context-manager self-return. В `qwen_executor.shared_executor` AST содержит
`return executor`, не пустой return: Astroid выводит `None` из `WeakValueDictionary.get`
и ветвь с Executor. Старый текст `NoneType` относился к первой альтернативе,
тогда как инфраструктурный тип находился во второй. Теперь проверяется и называется
сама offending-альтернатива; согласованная фабрика Domain-контракта разрешена.
Общего разрешения `hashlib`, `textwrap`, `copy`, `threading`, `concurrent.futures`
нет: дополнительные чистые операции требуют обоснования на уровне symbols,
а реальная работа с внешними ресурсами остаётся за Domain/UseCase.

При обновлении поставки переносите `_architecture_compat.py`, регрессии и вызов
installer в worker. После обновления плагина сначала пересмотрите каждое исправление,
затем выполните targeted unittest и полный static check.
