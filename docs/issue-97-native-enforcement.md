# Issue #97: native enforcement feasibility for generated dependency roles

Research only; no policy or consumer changes. Scope is the agreements in [map #94](https://github.com/ArtFilippov/quard/issues/94) and the [question in #97](https://github.com/ArtFilippov/quard/issues/97). Versions are pinned in [tools.json](../tools.json): Tach 0.35.1, clean-architecture-linter-plugin 1.2.2, Pylint 4.0.8. Findings below compare the *installed pinned packages* with [Tach's v0.35.1 source](https://github.com/gauge-sh/tach/tree/v0.35.1) and [plugin v1.2.2 source](https://github.com/noah-goodrich/pylint-clean-architecture/tree/v1.2.2); the live Tach [configuration](https://docs.gauge.sh/usage/configuration/), [layers](https://docs.gauge.sh/usage/layers/), [interfaces](https://docs.gauge.sh/usage/interfaces/) and [commands](https://docs.gauge.sh/usage/commands/) docs explain the user-facing controls. Where docs and pinned behavior differ, pinned code governs.

Historical audit: issue #128 later disabled reviewed production W9201 by policy;
current coverage is documented in [PROFILE.md](../PROFILE.md#tools-and-scope).

## What Tach can enforce

| Dependency row from #94 | Native fit and necessary qualification |
| --- | --- |
| External (not tracked in the **local** graph) | Leave external packages out of local `[[modules]]` and local role edges. Keep `tach-external`: it checks installed third-party imports against declared package dependencies, including `pyproject.toml`, independently of the local role graph. Do not set a module-level `depends_on_external` allowlist just to express `Contract -> External`: that option restricts *which external top-level imports* are allowed; `cannot_depend_on_external` bans them. Standard-library imports are exempt from its package declaration check. This is package-declaration checking, not proof that an external type is a contract or that external code performs no I/O. [Native external checker](https://github.com/gauge-sh/tach/blob/v0.35.1/src/checks/external_dependency.rs), [module config](https://github.com/gauge-sh/tach/blob/v0.35.1/src/config/modules.rs), [check-external docs](https://docs.gauge.sh/usage/commands/#tach-check-external), [Quard adapter](../src/quard/tach_worker_utils.py). |
| Contract -> Contract, External | One possible order puts Contract at the bottom; give every tracked file a module with an explicit `depends_on` list, and derive only *eligible* observed local dependencies, never automatically approve illegal imports. `Contract -> External` is permitted, **without** adding an I/O check to generated projects. Same-layer Contract imports still require exact declarations. An explicit `cannot_depend_on` for forbidden destinations can make errors independent of an accidentally permissive edge. [Native dependency checker](https://github.com/gauge-sh/tach/blob/v0.35.1/src/checks/internal_dependency.rs), [Tach layer rules](https://docs.gauge.sh/usage/layers/), [Quard generator](../src/quard/architecture_draft/contract_boundary_utils.py). |
| Infrastructure -> Contract, External, its own class only | Place Infrastructure above Contract. Forbid Infrastructure -> Infrastructure *between distinct files/modules*, even within a group, with `cannot_depend_on`; the layer order alone permits same-layer imports when declared. Tach treats references inside the same module as free, and cannot decide whether one class inherits another implementation, calls another class in the same file, or implements several group-local contracts. Those are class/ancestry checks outside Tach. [Native dependency checker](https://github.com/gauge-sh/tach/blob/v0.35.1/src/checks/internal_dependency.rs), [class-contract and folder ownership behavior](../PROFILE.md#tools-and-scope). |
| Envelopes -> Envelopes, Contract, Infrastructure, External | Put Envelopes above Infrastructure (if using a linear order), with exact file dependencies. No per-group restriction on envelope-to-envelope imports is specified by #94; assembly authorization comes from the one `envelopes/` directory *per group*, where present. Native imports are insufficient to enforce directory count/placement, inheritance, or whether a concrete class is assembled rather than merely imported. [Tach layers](https://docs.gauge.sh/usage/layers/), [Quard's Envelope boundaries](../src/quard/architecture_draft/contract_boundary_utils.py). |
| Bootstrap -> Envelopes, Contract, Infrastructure, External; never Bootstrap | Put Bootstrap highest but emit explicit Bootstrap -> Bootstrap prohibitions for *different modules*. Tach permits imports from the same module regardless of role; a single `main` directory and its nested files may still need class/assembly validation. Exactly one directory named `main` anywhere under `src/` needs a separate discovered-tree check, even if it contains no imports. [Native internal dependency checker](https://github.com/gauge-sh/tach/blob/v0.35.1/src/checks/internal_dependency.rs), [root-module config](https://docs.gauge.sh/usage/configuration/#the-root-module). |

Suggested Tach order: `Bootstrap, Envelopes, Infrastructure, Contract`. **Order is necessary but not sufficient**: upper layers may import all lower layers, so both Infrastructure -> Infrastructure and Bootstrap -> Bootstrap need explicit prohibitions; `cannot_depend_on` overrides `depends_on`. Keep `layers_explicit_depends_on = true`, `exact = true`, `forbid_circular_dependencies = true`, `ignore_type_checking_imports = false`, `root_module = "forbid"`, `respect_gitignore = false`, no `utility`/`unchecked`, and retain the native unused-ignore/reason/external-dependency rules. In particular, an omitted `depends_on` is permissive in Tach; an **empty** list is restrictive. Quard currently specifies these defaults and validates the *reviewed* path separately in [configured_architecture_draft.py](../src/quard/architecture_draft/configured_architecture_draft.py); do not change that reviewed validator to accept generated-only roles. [Tach configuration](https://docs.gauge.sh/usage/configuration/#modules), [internal implementation](https://github.com/gauge-sh/tach/blob/v0.35.1/src/checks/internal_dependency.rs).

Use file-level Tach modules for production `.py` and `.pyi` paths and exact symbol `[[interfaces]]` exports for proven local contracts (including validated re-exports); keep other cross-group symbols private to ordinary modules. The user's original rule explicitly **excepts `main/` and `envelopes/`** from the outside-group implementation ban. `visibility` plus `exclusive` can grant concrete-implementation imports only to proven Envelopes/Bootstrap modules, while keeping them private to all other outsiders. The existing generator exposes implementations to assembly modules, but also exposes all symbols to same-owner peers, so its interface rules still need revision for the stricter Infrastructure-to-Infrastructure ban. Re-export chains must be checked for provenance, including `__init__.py`/aliases, rather than approving a public-looking name or all of a package. A bare imported module has an empty member and passes Tach's interface check; arbitrary subsequent `pkg.Concrete` attribute access is not a guaranteed symbol-boundary check. [Tach interface checker](https://github.com/gauge-sh/tach/blob/v0.35.1/src/checks/interface.rs), [interface matching](https://github.com/gauge-sh/tach/blob/v0.35.1/src/interfaces/compiled.rs), [existing generator](../src/quard/architecture_draft/contract_boundary_utils.py), [Tach interface docs](https://docs.gauge.sh/usage/interfaces/). Also guard the package facade's own imports: Tach skips dependencies within the *same* module, so an `__init__.py` can still leak an implementation if exports/provenance aren't independently validated. [Native dependency checker](https://github.com/gauge-sh/tach/blob/v0.35.1/src/checks/internal_dependency.rs).

**Typing and stubs:** the pinned Rust import visitor includes `if TYPE_CHECKING:` imports when configured false, including relative/direct `from` imports, and attributes import offsets/lines; it is a syntactic import graph, not a class inheritance/annotation proof. The pinned internal checker calls `walk_pyfiles`, which selects `.py` **only**, although module resolution accepts `.pyi` (and prefers stubs): declarations/imports occurring only in a companion `.pyi` are *not* inspected by native `tach check`/`check-external` in this version. Quard currently parses stubs for boundary discovery but intentionally omits stub-only Tach `depends_on`; keep independent positioned `.pyi` analysis (and Pyright) for role/visibility/typing constraints and fail on unreadable/unresolved evidence instead of claiming Tach covered it. `if TYPE_CHECKING` is a limited syntactic condition, not semantic tracking of arbitrary deferred imports. [Import visitor](https://github.com/gauge-sh/tach/blob/v0.35.1/src/processors/import.rs), [file walker and resolver](https://github.com/gauge-sh/tach/blob/v0.35.1/src/filesystem.rs), [internal checker](https://github.com/gauge-sh/tach/blob/v0.35.1/src/commands/check/check_internal.rs), [Quard boundary builder](../src/quard/architecture_draft/contract_boundary_utils.py), [runner profiles](../src/quard/check_runner/runner_utils.py).

## Feasible enforcement split and trade-offs

1. **Prefer Tach for positioned *imports***: generate exact local modules, ordered layers and `cannot_depend_on` for forbidden pairs, retain native private-interface, cycle and unused-dependency results, `tach-external`, and the adapter's explicit exact pass (the native CLI's JSON branch exits before that pass). Keep `__init__.py` imports visible, do not run `tach sync` in normal checking. Trade-off: file-level modules make same-file interactions invisible and native symbol interfaces cannot prove every indirect re-export/attribute usage. [Tach CLI v0.35.1](https://github.com/gauge-sh/tach/blob/v0.35.1/python/tach/cli.py), [internal/interface checkers](https://github.com/gauge-sh/tach/tree/v0.35.1/src/checks), [Quard adapter](../src/quard/tach_worker_utils.py).
2. **Use separate, source-positioned Quard class/provenance checks for the semantic gap**: directory-owned groups/nested immediate folders, at most one `main`, one `envelopes/` per group, exact external base promoted to Contract repository-wide (not its package), local Protocol/abstract classes and explicit cross-group combined contracts, implementation-to-implementation and inheritance bans even within one module, signature/field/return types, qualified aliases and package re-exports in `.py` and `.pyi`. Name-derived current folder jobs and the current dependency-types rule alone are insufficient: the latter only prohibits a concrete class from another *module* in annotations outside assembly, not arbitrary same-module implementation references/inheritance. Retain independent Pyright/Pylint findings. [Map #94](https://github.com/ArtFilippov/quard/issues/94), [current Quard rules](../PROFILE.md#tools-and-scope), [generator](../src/quard/architecture_draft/contract_boundary_utils.py).
3. **Partition compatibility by generated marker vs reviewed config**, not by renaming the reviewed layer list or globally switching off IDs. Today [generated_architecture_utils.py](../src/quard/architecture_draft/generated_architecture_utils.py) still calls the legacy draft with `validate_ownership=False` and syncs the native map; [configured_clean_architecture_layers.py](../src/quard/clean_architecture_layers/configured_clean_architecture_layers.py) discards layers not in the five-name [policy list](../src/quard/policy_utils.py). Therefore simply changing `tach.toml` role names produces absent/inaccurate plugin mappings, in addition to old predicates above. A reviewed consumer still requires explicit acceptance and retains its native config and old compatibility behavior. Source and config failures must be exit **2**, violations exit **1**, success exit **0**; do not filter native findings, treat unresolved checks as passed, silently exclude stubs, or approve current imports. [README.md](../README.md#generated-architecture), [PROFILE.md](../PROFILE.md#architecture), [Quard adapter](../src/quard/tach_worker_utils.py), [COMPATIBILITY.md](../COMPATIBILITY.md#совместимость-с-clean-architecture-linter-plugin-122).

**Assembly exception clarified:** The original user requirement permits `main/` and `envelopes/` to see concrete implementations across groups. Generated Tach interfaces can grant this narrowly to proven assembly modules using `visibility` and `exclusive`; ordinary modules retain contract-only access, and Infrastructure still cannot depend on other Infrastructure, even within a group. Source/stub provenance checks must prevent package facades and aliases from widening that exception. [Map #94](https://github.com/ArtFilippov/quard/issues/94), [Tach interface visibility](https://docs.gauge.sh/usage/interfaces/#interface-visibility), [existing Quard assembly exposure](../src/quard/architecture_draft/contract_boundary_utils.py).
